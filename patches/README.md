# Bounded dependency security backports

`deepmerge@4.3.1.patch` is generated by Bun's native patch workflow. The user
approved this same-major security repair on 2026-10-29. It addresses
[GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), whose
upstream advisory lists no patched release as of that review.

The patch changes only the three object-property writes in `mergeObject` to
define enumerable, writable, configurable **own data properties**, avoiding an
inherited `__proto__` setter. Source, CommonJS and UMD distribution files carry
the same change. Array merging and existing source-key guards are preserved.
Upstream MIT licensing and copyright remain unchanged in the installed package;
this patch is not a replacement upstream release or a general security audit.

The regression exercises the vulnerable **target-copy** path and a null-prototype
target/source path, plus the published CommonJS/UMD runtime entrypoints and ordinary
array/object behavior. It failed on the original package and passes after the
patch. A separate clean `bun install --frozen-lockfile --ignore-scripts` in an
owned manifest-only directory reproduces both runtime builds from the committed
patch/lock, rather than relying on a modified local cache. The upstream source
`index.js` is not standalone in the published package: its development-only
`is-mergeable-object` dependency is bundled into runtime builds, so it is not
incorrectly counted as a third runtime acceptance case.

Registry audit tools still report this package by its original version. Do not
suppress that result or describe a registry audit as clean. Report the applied
backport and executable regression/reproduction evidence separately. Remove the
backport only after reviewing an upstream fixed release and rerunning the same
gates. Bun **1.4.2** is the repository-pinned installer; its native frozen install
has been verified with the version-scoped override/patch lockfile.
